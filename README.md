# ELVARN V1

A small decoder-only Transformer language model written in PyTorch, with a
fixed byte-level BPE tokenizer, a document-level train/validation split, and a
local browser chat UI that shows the text generated by your own checkpoint.

ELVARN is a small model trained on a limited corpus. Its replies are generated
text and can be wrong, repetitive or incomplete. Nothing in the training data
is "verified" just because it is in the corpus; the domain blocks are marked
`Unverified - pending source check`.

| `backend/training/checkpoints/` | Old word-vocabulary checkpoints. Not compatible. Untouched. |
| `backend/api/` | FastAPI server and model loader. |
| `frontend/index.html` | The chat UI. |
| `backend/tests/` | Tests. |

## Commands (Windows PowerShell, from the project root)

```powershell
# 1. Activate the virtual environment
cd "E:\MADHAVAN\Z I P N O W\Super Intelligence\universe"
.\.venv\Scripts\Activate.ps1

# 2. Install dependencies
python -m pip install -r backend\requirements.txt

# 3-5. Prepare corpus, train the BPE tokenizer, split + tokenize the data
python backend\training\prepare_all.py
#    (or run the steps one by one)
python backend\tokenizer\train_bpe.py
python backend\training\build_dataset.py

# 6. Smoke test (30 steps, writes to checkpoints_bpe\smoke, does not touch the real run)
python backend\training\train_batch.py --smoke

# 7. Full training (3000 steps, about 25-40 minutes on CPU)
python backend\training\train_batch.py

# 8. If training is interrupted, continue from the last saved state
python backend\training\train_batch.py --resume

# 9. Start the backend + UI
python -m uvicorn backend.api.server:app --port 8000
```

Then open <http://127.0.0.1:8000> in Chrome or Edge, type `hii` and press Enter.

After a new training run finishes, click **Reload latest model** (in the ⚙️
panel) or restart the server. The status line under the title shows the loaded
checkpoint and training step.

Run the tests:

```powershell
python -m pytest backend\tests -q
```

## How the pieces fit

1. `corpus.py` turns each raw file into documents (one per `<TAG>` block, or
   paragraph groups for plain text), removes duplicates, assigns about 5% of
   documents to validation, and removes any training document that is a
   near-duplicate of a validation document. Splitting is by document, before
   any sequences are made, so validation text is never seen in training.
2. `train_bpe.py` trains the tokenizer on the **training** documents only.
   Special tokens: `<PAD>`=0, `<UNK>`=1, `<BOS>`=2, `<EOS>`=3, plus the four
   category tags. The vocabulary is fixed after training.
3. `build_dataset.py` writes each split as `<BOS> text <EOS>` token streams.
4. `train_batch.py` samples random windows of 128 tokens, predicts the next
   token at every position, and ignores `<PAD>` in the loss. It evaluates on the
   validation split every 250 steps. `final.pt` holds the best-validation
   weights and `latest.json` points at it. The server only loads a run that
   is marked `completed`, and refuses a checkpoint whose tokenizer hash
   differs from the saved tokenizer.
5. The server builds a prompt in the same format as the training data (for
   example `<CASUAL_CONVERSATION>\nUser: hii\nAssistant:`), generates token by
   token with the loaded model, and returns the text. The UI shows it
   unchanged. Generation stops at `<EOS>`, at the start of a new
   `User:`/`Question:`/block, or at the token limit. Use **Show raw model
   output** in the lab panel to see everything the model produced.

## Model

Token + learned position embeddings, 2 decoder blocks (4 attention heads,
post-norm, GELU MLP), final LayerNorm, output head tied to the token embedding.
Embedding 128, hidden 256, context 128 tokens, about 0.8M parameters.
Dropout 0.1. Everything runs on CPU.

Choices worth knowing:

* **Vocab 4096.** The corpus is only a few hundred thousand tokens. A larger
  vocabulary would leave many tokens rarely seen; a much smaller one makes
  sequences longer. 4096 is a middle point. Byte-level BPE never needs `<UNK>`.
* **4 heads** instead of 1: same parameter count, and each head can learn a
  different pattern.
* **Context 128** instead of 64: many answers are longer than 64 BPE tokens.
* The old word-level checkpoints cannot be loaded: token ids are different.

## API

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | Server / model / tokenizer status and any load error. |
| `GET /api/model` | Loaded checkpoint, step, parameters, vocabulary. |
| `POST /api/chat` | `{text, mode, history, temperature, top_k, max_new_tokens, greedy}` |
| `POST /api/generate` | Same body; for testing generation settings. |
| `POST /api/reload` | Load the newest completed checkpoint (old one kept if the load fails). |

Modes: `chat`, `domain`, `english`, `humour`, `raw`. Interactive docs: `/api/docs`.

## UI

Colourful responsive chat for desktop and phone. Voice input (🎤) and read-aloud
(🔊) use the browser's built-in speech features: use Chrome or Edge on
`localhost`. Voice input may send audio to the browser vendor's speech
service. Settings (temperature, max tokens, top-k, greedy, voice, speed,
listening language) are in the ⚙️ panel.
